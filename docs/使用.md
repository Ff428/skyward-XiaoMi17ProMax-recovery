# 使用

这台手机上的 Skyward：怎么刷进去、怎么解开 data、怎么装系统、充电与录屏怎么用。

## 刷入与进入

```sh
adb shell getprop ro.boot.slot_suffix       # _a 就写 recovery_a，_b 就写 recovery_b
adb reboot bootloader
fastboot flash recovery_a skyward-OS4.0.8.0-XiaoMi17ProMax.img
fastboot reboot recovery
```

- 需要已解锁 BL。只动 `recovery_<slot>`，`boot` / `init_boot` 不碰。
- 出问题把原厂 recovery 刷回同一个分区即可。
- **不要用 recovery 里的「检查更新」**：那是 Skyward 官方自更新，会把官方镜像写回分区，本仓库的定制全部丢失。

进入后首页是设备卡，下面按分类摆：**无线网络**、**文件管理**、**模块管理**、
**安装刷机**四条各自一行，然后是三张卡片——**刷机备份 · 3**（文件传输 / 创建备份 /
恢复备份）、**文件模块 · 5**、**系统设置 · 11**，最后是**其他 · 8**（设置、首页排序、
日志、清除数据、系统更新、Skyward 更新、重启、关机）。四张卡默认都折起来，点栏头展开。
三十一条一条不少。分类、「其他」、每条名字、首页标题都能改，见下面「首页怎么摆」。
顶部状态栏只有时间（录屏时时间后面多一个红点），右侧是电池与网络。

## 主题颜色与壁纸

设置 → **主题颜色**。壁纸在最上面，壁纸那块与下面三组颜色都能折起来
（右边一枚「展开／收起」+ 圆钮）。

- **壁纸**：点「挑一张图」进文件夹。默认 `/sdcard/Skyward`，往里丢 jpg、png
  就出现在列表里，正方形缩略图，选中的右下角打勾。展开壁纸这块，五根滑杆
  并在一张卡里：前景 / 压暗 / 缩放 / 左右 / 上下。
  - **前景**：0 全透、只剩壁纸；1 全不透明、就是页面底色。页面上的字一直压在
    这一层上，所以调大文字更稳、调小壁纸更清楚。
- **主题**：亮色、深色、柔光（淡蓝透光）、暗光（深灰蓝）。
- **强调色 / 页面背景 / 磁贴底色**：各三个分量（R/G/B），点「用主题自带的」
  回到当前主题的配色。页面背景换掉后，卡片与文字按它的亮度自动翻深浅。
- 磁贴底色只管控制中心里**关着**的那些磁贴；点亮的仍然用主色。

选中的壁纸与颜色都记在 `/metadata/skyward/settings.json`
（`wallpaper_dir` / `wallpaper_file` / `foreground` / `accent` / `background` /
`tile_tint`），换语言不会丢。

## 首页设备卡

名字与副标题下面一行四格，每格上排数值、下排说明：

| 格 | 数值 | 说明 |
|---|---|---|
| 当前槽位 | `A` / `B` | 取 `ro.boot.slot_suffix`，读不到就不出这一格 |
| 数据分区 | `已解密` / `加密` | 写在解密状态上 |
| 可用空间 | `380.4GB` | `/data` 的可用量 |
| 电池 | `100%` | 下排是状态；插着线时带这一刻的功率（`充电中 · 7.9W`），**充到 100% 也给**，拔线只剩状态 |

整行（名字与读数）都是点开设备详情的入口；按住时高亮用卡片自己的圆角。

## 首页怎么摆

首页由四段拼起来：**置顶**、若干**分类**、**「其他」**、以及最上面的设备卡。
每一条入口都在其中恰好一个位置，`normalize()` 保证不重不漏——所以挪动永远不会丢条目。

| 想做 | 怎么做 |
|---|---|
| 改顺序 | 「首页排序」→ **按住**某一条 0.4 秒拎起来，往上往下拖，它跟着落到第几格；**拖到别的栏那几行上就进那一栏**（「其他」里的能拖进刷机备份、也能拖进文件模块）。松手即存；短按拎起来、再点另一条也行 |
| 建分类 | 排序页底部「新建分类」，起个名字，再把条目拖进去 |
| 删分类 | 排序页里那一栏的铅笔按钮 →「删除分类」，里面的条目回「其他」 |
| 折叠一栏 | 点栏头就折起 / 摊开，**改了就记住**，重进 recovery 还是那个样子 |
| 记不记得展开状态 | 「首页排序」页底部、「新建分类」下面那一行「首页分类展开」：开 = 重进时按上次的展开/收起，关 = 每次起来全折起 |
| 挪「其他」 | 栏头右边那两枚（三横杠 + 上箭头 / 下箭头）就是上移、下移，按下去那一栏会滑到新位置；「其他」也能挪到任一分类前面，但它自己不能进分类 |
| 改名字 | 排序页里任一条的铅笔 → 输入框；分类名、栏目名、「其他」的名字都能改 |
| 改首页大字 | 排序页顶部标题那一行，点铅笔 |
| 折叠一栏 | 点栏目头右边的箭头；「其他」也一样 |
| 加磁贴 | 控制中心「添加磁贴」，候选按「开关与动作」和「页面」分两组 |

改过的名字搜索也认：搜新名字能搜到，旧名字搜不到。名字存在设置文件里，
按条目的短 id 存（`charge` / `relabel` 这类），所以换语言不会丢。

## 布局备份

排序页底部「布局备份」→ 一页两件事：

- **导出**：默认写 `/sdcard/Skyward/layout-<时间戳>.json`；也可以点「挑个位置」，
  在文件管理那套界面里选目录。
- **导入**：列出目标目录里所有 `layout-*.json`，点一行就套用；`kind` 不对、
  `version` 不认识的文件直接跳过，不动现在的首页。
- **删除**：每一份右边有一枚红色垃圾桶，点它删掉那个 `.json`（只删文件，不改
  现在的首页），删完列表立刻刷新。

一个布局文件里装的是：首页标题、各分类（名字 / 图标 / 折叠 / 里面的条目）、置顶、
「其他」的顺序与名字、每一条的自定义名字、磁贴的排布。换机、换版本、手滑改坏了
都能拿它回到原样。

## 文件传输

首页那条「文件传输」点进去是**它自己的一页**，开关就在页上。开关状态说的是事实：

| 页面上的说法 | 意思 |
|---|---|
| 关着 | 没有在跑服务 |
| 开着但没连 | 服务在跑，还没人连上来 |
| 连着 | 有设备连上了 |

设置页里那一段已经删掉——同一个开关只有一处，免得两边的说法打架。

## 解密 data

`device.toml` 里 `[data] weaver_first = true`：**weaver 槽优先，gatekeeper 绑定的 blob 兜底**。

1. 起 `android.hardware.weaver-service.nxp-qti`（NXP weaver），它经 OMAPI 打开 eSE 里的 applet 取槽；
2. OMAPI 由 `se_omapi` 提供（`android.se.omapi.ISecureElementService/default`）；
3. 取到的槽解开 `/data/system_de/<user>/` 旁的 `<id>.weaver` 与 `<id>.spblob`；
4. weaver 不可用或 `weaver_first` 关掉时，改走 credential 服务（keymint + gatekeeper）绑定的那份 blob，结果等价。

这条链依赖四个前提，镜像里都已经做掉：

| 前提 | 不满足会怎样 |
|---|---|
| secure_element 注册 `eSE1` | servicemanager 拒绝 addService，HAL abort，NXP weaver 的通道一起死 |
| `se_omapi` 有 VINTF 描述（`/system/etc/vintf/manifest/se_omapi.xml`） | weaver 报 `Failed to start omapiSeService`，`/data` 仍锁 |
| `nxp-nci` 模块加载 | eSE 通道不通 |
| 八个服务按 `device.toml` 的顺序起来 | 起晚了同样解不开 |

八个服务（`device.toml` 定义顺序）：`qseecomd`、`hlosminkdaemon`、
`android.hardware.security.onekeymint-service-qti`、
`android.hardware.gatekeeper-rust-service-qti`、
`android.hardware.weaver-service.nxp-qti`、
`android.hardware.secure_element-service.qti`、
`android.hardware.boot-service.qti`、`se_omapi`。

段位一行在启动控制服务起不来时显示「A（当前）」——按当前运行的系统算，不再「无法读取」。

## 安装系统

安装用自写的 payload applier，不走 `update_engine`（除非包本身不支持直写）。

**两条路**：

```
install:
  Payload::open()                 # 从 sideload / FUSE / 本地文件读 CrAU 头
  applier::plan()  ── 说不行 ──→  `install: the payload is left to update_engine: <原因>`
        │ 说行
        ↓
  applier::write()                # 解压直写，不建 COW
  applier::check()                # 按分区并行读回，SHA-256 比对
  skyward_vab::set_next_slot()    # 让下一个槽启动
```

**写第一个字节之前就判掉**（`applier::plan()` 扫全包、汇总成一句原因）：

| 情形 | 日志里的原因 |
|---|---|
| 块大小不是 4096 | `the payload measures its blocks in {n} bytes, and this recovery writes 4096` |
| 差量包 | `the payload writes only what changed, and the rest of super as it is` |
| 有本程序不认识的 op | `the payload has operations this recovery does not apply: …` |
| `super` 读不出来 | `super cannot be read for slot {B}: …` |
| 分区在包与 super 里大小不同 | `…so the layout would have to change` |
| 物理分区装不下 | `…and the partition holds {m}` |
| 单个 op 超过 512 MiB | `an operation writes {n} bytes, past the 536870912 this holds` |

**写入与校验**：

- 读线程按顺序读 payload，解压写盘的是 `cores - 1`，`clamp(2, 8)`（本机 7 条）；
- 数据直接 `pwrite` 到目标分区，不建 COW，写完这个槽就是完整的，不需要合并；
- 校验按分区并行，每分区一条 SHA-256，读块 1 MiB；
- 真机实测 11.29 GB / 71 s（162.0 MB/s），读回 69.1 s（167.3 MB/s）。

**同一个会话里接着做完**：定下一个启动槽、把 recovery 自己写回、补 root
（手机上的 `ksud` / `magiskboot` 原地重打再读回比对）、备份并写回 vbmeta
（`/sdcard/Skyward/vbmeta/vbmeta_<槽>-r<回滚>-<unix秒>.img`）。

**页面三个阶段**：安装（读包校验 → 写入 → 读回）、合并（映射快照 → 合并 →
可重启）、root（取回启动镜像 → 重打 → 写回比对）。

## 充电

入口在首页「其他」里的**充电设置**（也能拖进任何分类，或者摆成控制中心的磁贴）；
右侧显示这一刻进电池的功率，拔了线只剩名字。

点进去是五段：现在 / 充电档位 / 温控 / 充电器 / 电池。

| 档位 | 起哪些小米服务 | 实测量 |
|---|---|---|
| 默认 | 两个都不起 | 5W+ |
| 快充 | `micharge` | 10W+ |
| 超快充 | `micharge` + `batterysecret`（认证进程） | 40W+（原装充电器） |

档位决定 recovery 启动哪些程序，**下次进 recovery 才生效**（插着线改不了）。

**温控**：上限 40–55 °C，每秒跟一次电池温度；到线就把档位降一级，先把新档位写进设置
再重启回 recovery。默认档不启用这一项。开机后 60 秒内不判（免得余温连降两次）。

设置落在 `/metadata/skyward/settings.json`（`charge_mode` / `thermal_guard` / `thermal_limit`）。

**判据**：

```sh
dmesg | grep "charge step kept"
# 超快充：the charge step kept is fastest: 2 program(s) of the phone's that settle it were started
```

## 录屏

recovery 里没有 MediaCodec，也没有 ffmpeg：画布 → 块平均缩放 → BT.601 转 YUV420 →
openh264 编 H.264 Baseline → 按采集时刻把 sample 装进 MP4。缩放与编码都在后台线程。

**入口**：控制中心的录屏磁贴、首页「其他」里的「录屏」、搜索。

**设置**（录制中锁定，停下才能改）：

| 项 | 档位 |
|---|---|
| 分辨率 | 原画 1200×2608 / 高清 900×1956 / 标准 600×1304 / 流畅 450×978 |
| 画质 | 高 6.5 Mbps / 中 3.8 Mbps / 低 2.3 Mbps（标准档 @30 帧） |
| 帧率 | 60 / 30 / 24 / 15 |
| 容器 | MP4（H.264 Baseline） |

默认标准 + 中 + 30 帧。分辨率那行的副标题按目标码率算每分钟体积，例如
`600×1304 · 每分钟约 28 MB`。

**计时胶囊**：录制中右上角，可拖动；点左侧圆点暂停 / 继续，点右侧方块结束这一段。

**文件**：`/sdcard/DCIM/Screenrecords/Screenrecord_<日期>-<时间>.mp4`，上限 3.9 GB
（`stco` 是 32 位偏移）。`moov` 写在文件末尾，录制中途断电那份文件打不开。

**不上手机验容器**：

```sh
python scripts/check_record.py take.mp4
```

它查顶层盒子首尾相接、`stsz` 合计等于 `mdat`、`stsc` + `stco` 覆盖每个 sample、
`avc1` + `avcC` 的 SPS / PPS、每个 sample 的 4 字节长度前缀、关键帧表与 `stts`。

**日志**：

```
record: started, 600×1304 · 3.8 Mbps · 30 fps · MP4 (H.264)
record: stopped after <N> frames, <秒> s, <M> MB, <MB/s> MB/s (<left out> frames left out, <P> pauses)
record: paused / record: carried on
```

`frames left out` 应为 0；`MB/s` 应接近设置页报的目标码率。

## 其他功能

| 功能 | 怎么用 |
|---|---|
| 文件管理 | 「内部存储」旁一枚 `sdcard` 一步进 `/sdcard`；U 盘单独一页；四圆钮是排序 / 多选 / U 盘 / 搜索 |
| 无线 | 最多记 8 张网、最近优先；连不上换下一张、最多三轮。名单在 `/metadata/skyward/wlan`，`auto=` / `keep=` 两行加每网一节（SSID / 密码 / 加密方式全是 hex）；`keep` 只表示「以后连上的还记不记」，关掉不会擦已记住的 |
| 控制中心 | 磁贴可拖拽排序、可移除，28 种任选，摆法存 `/metadata/skyward/tiles` |
| 输入法 | 中文 26 键打拼音，候选条在上方（一页 3 条），点候选或空格选第一个；中 / 英那一枚一按就换；密码、网址这类页始终小写。键盘页上下滑不滚页面，左右滑翻候选 |
| 备份 | 按分区备份到内部存储或 U 盘；恢复前校验摘要 |
| 模块管理 | 从 `vendor_boot` / `vendor_dlkm` / `vendor` / `system_dlkm` 取模块，按 `devices/popsicle.toml` 的列表加载 |
| 应用管理 | 系统应用的停用 / 启用；停用的收在「已停用」页，点一下排 `enable` 回来。队列在 `/data/adb/skyward/pm-queue`，脚本在 `/data/adb/service.d/` 等位置，结果写 `pm-state` / `pm.log` |
| 第二系统 | 主系统之外再装一套，启动时选；第二系统的第一个程序静态链接 |

## 日志与排错

| 现象 | 看哪里 | 处理 |
|---|---|---|
| 能开机但解不开 `/data` | `dmesg` 里 `weaver` / `keymint` / `Failed to start omapiSeService` | 确认补丁层进过镜像（`augment_stock.py`），`se_omapi.xml` 在 VINTF 清单里 |
| 充电只有几瓦 | `dmesg \| grep "charge step kept"` 显示 `plain: 0 program(s)` | 档位是「默认」或设置没生效；改档位后重启回 recovery |
| 录屏文件打不开 | `python scripts/check_record.py <file>` | 录制中断电（`moov` 没写完）只能重录 |
| 中文候选不对 | 键盘页左右滑翻页 | 候选一页 3 条，空格选第一个 |
| 震动不响 | `dmesg` 里马达是否就绪 | cs40l26 要等固件下载完，开机头几十秒可能还没有 |

系统日志：`/mnt/vendor/persist/update_engine.log`（回退到 `update_engine` 时它自己的日志，
收尾抄最后 4 MB 过去）。
